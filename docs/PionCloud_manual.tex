\begin{abstract}
\noindent
\picloud{} is a modular C++ library and executable for computing the
leading pion-cloud contributions to nucleon structure functions
$F_2^{(\pi N)}(x)$ and $F_2^{(\pi N)}(\theta_h)$ in the Sullivan
process.  It is a direct, validated port of three Fortran programs
(\texttt{3Var\_x.f}, \texttt{3Var\_theta.f}, \texttt{f2\_pi\_sub.f90})
by T.~Hobbs and W.~Melnitchouk, extended with configurable scan modes,
ROOT output, CTEQ6 neutron structure function evaluation, and a static
library interface for embedding in other programs.
The code was developed as a framework for BoNuS/TDIS analysis at JLab.
\end{abstract}

\section{Introduction}
% ============================================================

\subsection{Physics background}

In the Sullivan process, a nucleon $N$ fluctuates into a virtual
meson--baryon pair ($M B$):
\begin{equation}
  N \;\longrightarrow\; M + B
\end{equation}
The leading contributions from the pion cloud are:
\begin{align}
  n &\to \pi^- + p \quad \text{(charge exchange, } \mathit{dis}=0\text{)} \\
  p &\to \pi^0 + p \quad \text{(neutral exchange, } \mathit{dis}=1\text{)}
\end{align}
with subdominant contributions from $\rho N$ and $\pi\Delta$ channels.

The tagged structure function, observed when the recoil proton is
detected in a specific momentum and angular window, is:
\begin{equation}
  F_2^{(\pi N)}(x;\,\Delta k,\,\Delta\theta_h)
  = \int_{\Delta k,\,\Delta\theta_h}
    \rho_\mathrm{PS}(\theta_h, k)\;
    f_{\pi N}(y, k_T)\;
    F_2^{\pi}(x/y,\, Q^2)\;
    dk\, d\theta_h
\end{equation}
where $\rho_\mathrm{PS}$ is the phase-space Jacobian, $f_{\pi N}$ is
the pion splitting function, and $F_2^\pi$ is the pion structure
function evaluated using GRV92 parton distributions.

The ratio $F_2^{(\pi N)} / F_2^n$ is the core BoNuS observable ---
it gives the fractional pion-cloud contribution to the neutron
structure function for a given experimental acceptance.

\subsection{Code history}

The original Fortran programs were written by T.~Hobbs (2013--2014)
with modifications by W.~Melnitchouk.  The C++ port
(\picloud{}) preserves the physics exactly while adding configurability,
a library interface, and ROOT output.

Key references:
\begin{itemize}
\item TDIS proposal~\cite{TDIS15}, Sec.~``Pion cloud model'' and
  Figs.~5, 6, 37, 46, 47: the calculations that the Fortran codes were
  written for and that \picloud{} reproduces (Sec.~\ref{sec:validation}).
  Also T.~J.~Hobbs~\cite{Hobbs15}, Fig.~2.
\item Holtmann, Szczurek, Speth (HSS)~\cite{HSS96}: $\Lambda$ values
  constrained by inclusive $pp\to nX$ data, used as defaults
  (labelled ``HSS'' in the Fortran sources).
\item Gl\"{u}ck, Reya, Vogt (GRV92)~\cite{GRV92}: pion parton distributions.
\item Pumplin et al.\ (CTEQ6)~\cite{CTEQ6}: nucleon PDFs.
\end{itemize}

\section{Building}
% ============================================================

\subsection{Prerequisites}

\begin{itemize}
\item CMake $\geq 3.14$ or g++ $\geq 7$
\item C++17 or later
\item \textbf{gfortran} (for CTEQ6 Fortran library; optional but recommended)
\item \textbf{ROOT} $\geq 6$ (optional; required for \texttt{.root} output)
\end{itemize}

\subsection{Full build (ROOT + CTEQ6)}

\begin{lstlisting}[style=bashstyle]
source /path/to/root/bin/thisroot.sh
cmake -B build -DUSE_ROOT=ON -DUSE_CTEQ6=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
# binary: build/PionCloud
# tests:  build/PionCloudTests
\end{lstlisting}

\subsection{Without ROOT or CTEQ6}

\begin{lstlisting}[style=bashstyle]
cmake -B build -DUSE_ROOT=OFF -DUSE_CTEQ6=OFF
cmake --build build
\end{lstlisting}

Without CTEQ6: $F_2^n$ and the ratio are set to zero.
Without ROOT: only ASCII output is produced.

\subsection{Direct g++ (no CMake)}

\begin{lstlisting}[style=bashstyle]
# No optional dependencies
g++ -std=c++17 -O3 -Iinclude \
    src/Calculator.cc src/InputReader.cc src/OutputWriter.cc src/main.cc \
    -o PionCloud

# With ROOT and CTEQ6
gfortran -O2 -c CTEQ6/Cteq6Pdf-2007.f -o Cteq6Pdf.o
g++ -std=c++17 -O3 -Iinclude -DHAVE_ROOT -DHAVE_CTEQ6 \
    src/Calculator.cc src/InputReader.cc src/OutputWriter.cc src/main.cc \
    Cteq6Pdf.o $(root-config --cflags --libs) -lgfortran -o PionCloud
\end{lstlisting}

\subsection{Scan modes}

\picloud{} has four scan modes, selected by \inikey{scan\_mode}:

\begin{center}
\begin{tabular}{llp{4.2cm}p{3.8cm}}
\toprule
\textbf{Mode} & \textbf{Output} & \textbf{Integrated over}
  & \textbf{Mirrors} \\
\midrule
\code{x}     & $F_2^{(\pi N)}(x)$
  & $(\theta_h, |\vec{k}|)$
  & \texttt{3Var\_x.f} \\
\code{theta} & $F_2^{(\pi N)}(\theta_h)$
  & $(x, |\vec{k}|)$
  & \texttt{3Var\_theta.f} \\
\code{kbin}  & $F_2^{(\pi N)}(x;\Delta k,\Delta\theta_h)$
  & $(y, k_T)$ with $|\vec{k}|$ and $\cos\phi_k$ gates
  & \texttt{f2\_pi\_sub.f90} \\
\code{all}   & all of the above & --- & --- \\
\bottomrule
\end{tabular}
\end{center}

\subsubsection{\code{x} scan}

Integrates over the hadron production angle $\theta_h$ and the recoil
proton momentum magnitude $|\vec{k}|$ at each output Bjorken-$x$ point.
Matches \texttt{3Var\_x.f} exactly.  Useful for computing
$F_2^{(\pi N)}(x)$ as a function of $x$ for a given $|\vec{k}|$ tagging
window.

\subsubsection{\code{theta} scan}

Integrates over $x$ and $|\vec{k}|$ at each output angle $\theta_h$.
Matches \texttt{3Var\_theta.f} exactly.  Used to produce
plots of the angular distribution $F_2^{(\pi N)}(\theta_h;\Delta x, \Delta k)$
such as Fig.~47 of the TDIS proposal~\cite{TDIS15}
(reproduced in Fig.~\ref{fig:fig47}).
The internal $x$ and $|\vec{k}|$ integration ranges are controlled by
\inikey{x\_min\_th}, \inikey{x\_max\_th}, \inikey{k\_min\_th},
\inikey{k\_max\_th}:
\begin{itemize}
  \item \textbf{Left panel} (Fig.~47): use defaults
    ($\Delta x=[0, 0.6]$, $\Delta k=[0, 500]$~MeV).
  \item \textbf{Right panel} (Fig.~47): set
    \inikey{x\_min\_th=0.05}, \inikey{k\_min\_th=0.060},
    \inikey{k\_max\_th=0.250}.
\end{itemize}

\subsubsection{\code{kbin} scan}

Mirrors the \texttt{f2\_pi\_sub.f90} subroutine.  Integrates over
$(y, k_T)$ at each output $x$ point with:
\begin{enumerate}
  \item An angular acceptance gate on $\cos\phi_k \in [\code{cosph\_min},\,\code{cosph\_max}]$
    (default: $\cos 70^{\circ}$--$\cos 30^{\circ}$, i.e.\ $[0.342,\,0.866]$).
  \item A $|\vec{k}|$ magnitude window $[\code{k\_min},\,\code{k\_max}]$.
\end{enumerate}
The $|\vec{k}|$ magnitude is computed analytically from $(k_T, y)$:
\begin{equation}
  |\vec{k}| = \sqrt{k_T^2 +
    \frac{\left[k_T^2 + (1-(1-y)^2)m_N^2\right]^2}
         {4\,m_N^2\,(1-y)^2}}
\end{equation}
This mode is used to produce the four $|\vec{k}|$-bin curves and the
individual channel contributions ($\pi N$, $\rho N$, $\pi\Delta$) of
Figs.~5, 6 and 37 of Ref.~\cite{TDIS15} (Figs.~\ref{fig:fig5}--\ref{fig:fig37}).

Note that $\cos\phi_k>0$ for every $(y,k_T)$, so the recoil nucleon
always goes forward and an upper angle of $90^\circ$ is the same as
$180^\circ$.  For $x\geq0.05$ and $|\vec{k}|\leq 400$~MeV the
$70^\circ$ upper cut is also practically inactive (effect $<0.5\%$),
because $y\geq x$ keeps the recoil forward of $\approx 70^\circ$.

\textbf{Note:} \texttt{3Var\_theta.f} and \texttt{3Var\_x.f} hardcode

The published TDIS figures~\cite{TDIS15} are reproduced with
$\theta_e = 35^{\circ}$ for \emph{all} modes, including kbin
(Sec.~\ref{sec:validation}).  The value $\theta_e = 12^{\circ}$ used when
\texttt{f2\_pi\_sub} was called from \texttt{f2\_pi\_ranges.c} gives a lower
$Q^2$ and tagged curves that are 3--10\% higher at $x\gtrsim0.15$.

\subsection{Physics --- channel selection}

\begin{center}
\begin{tabular}{llp{7.2cm}}
\toprule
\textbf{Key} & \textbf{Default} & \textbf{Description} \\
\midrule
\inikey{contribution} & \texttt{pion}
  & Channel: \texttt{pion} (0), \texttt{rho} (1), \texttt{pi\_delta} (2), \texttt{rho\_delta} (3, v1.4) \\
\inikey{dissociation}  & \texttt{charge\_exchange}
  & Charge config: \texttt{charge\_exchange} (0), \texttt{neutral} (1) \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Charge exchange} (\textit{dis}=0): $n \to \pi^- + p$
(or $p\to\pi^+ n$).  Isospin factor $= 2$.  Used for the
$\pi N$, $\rho N$, $\pi\Delta$ comparisons (Figs.~6 and 37 of~\cite{TDIS15}).

\textbf{Neutral} (\textit{dis}=1): $p \to \pi^0 + p$.
Isospin factor $= 1$.  Used for the proton-target curves
(Figs.~5, 46, 47 of~\cite{TDIS15}).

\textbf{Each run gives one charge state.}  The total pion-cloud
contribution of a nucleon sums both charge states (isospin factors
$1+2=3$).  Multiply a \emph{neutral} result by 3, or a
\emph{charge-exchange} result by $3/2$, to obtain the total
$F_2^{(\pi N)}(x)$ (the violet ``fully integrated'' curves of the
published figures; see Sec.~\ref{sec:validation}).

\subsection{Physics --- cutoff parameters}

\begin{center}
\begin{tabular}{lll}
\toprule
\textbf{Key} & \textbf{Default} & \textbf{Description} \\
\midrule
\inikey{lambda}       & 1.56  & $\Lambda$ for $\pi N / \rho N$ vertex [GeV] \\
\inikey{lambda\_delta} & 1.39 & $\Lambda$ for $\pi\Delta$ / $\rho\Delta$ vertex [GeV] \\
\bottomrule
\end{tabular}
\end{center}

For the $s$-dependent exponential form factor (\texttt{exp\_s}),
$G_{\pi N}=\exp[(M^2-s_{\pi N})/\Lambda^2]$, the values constrained by
inclusive $pp\to nX$ data~\cite{HSS96} (converted to this convention,
see~\cite{TDIS15}) are $\Lambda_{\pi N}=\Lambda_{\rho N}=1.56\pm0.07$~GeV
and $\Lambda_{\pi\Delta}=1.39\pm0.07$~GeV.
The $\pi\Delta$ channel always uses \inikey{lambda\_delta};
\inikey{lambda} has no effect on it.

\textbf{A cut-off belongs to a regulator.}  Fitted values differ by a
factor $\sim5$ between form factors: McKenney \textit{et al.}~\cite{McK16}
find 1.33~GeV (\texttt{exp\_s}), 0.85~GeV (\texttt{exp\_t}) and 0.27~GeV
(\texttt{pauli\_villar}) from the same data.  Up to v1.3 the default was
Pauli--Villars with 1.33~GeV, a pairing that matches no fit and gave
$F_2^{(\pi N)}$ 1.6--1.9 times larger than the HSS model; v1.4 defaults to
\texttt{exp\_s} / 1.56~GeV and warns when $\Lambda$ is far outside the
published range of the chosen regulator.  Recommended values for $\Lambda_{\pi N}$
with \texttt{exp\_s}:
\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Value} & \textbf{Meaning} \\
\midrule
$\Lambda = 1.56$~GeV & HSS central value \\
$\Lambda = 1.63$~GeV & HSS $+1\sigma$ \\
$\Lambda = 1.48$~GeV & HSS $-1\sigma$ \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Integration method (v1.4).}  The kbin scan now uses the
\emph{exact} method by default (Sec.~\ref{sec:v14}): \inikey{ny},
\inikey{nkt} and the \inikey{precision} presets act \emph{only} on the

\textbf{Performance note (grid method):} \inikey{nkt=50000} matches the Fortran

reason to lower it.  With \inikey{nkt=5000} the result changes by
$\lesssim0.2\%$, rising to $\sim1\%$ only next to the kinematic end point
where $F_2^{(\pi N)}\to0$.

\section{Changes in v1.4 (and how they were verified)}
\label{sec:v14}
% ============================================================

Every change is listed in \texttt{CHANGELOG.md} with its motivation, its
evidence and its numerical effect.  The rule (see \texttt{CONTRIBUTING.md})
is: a change either reproduces all 23 validation runs \emph{bit for bit},
or it changes numbers on purpose, with a reference, a measured effect and a
test that fails on the old code.

\subsection{How the results are verified}

\begin{enumerate}
\item \textbf{Against the published figures.}  The TDIS curves of
  Sec.~\ref{sec:validation}, extracted exactly from the vector graphics of
  PR12-15-006, are reproduced to $\approx1\%$ (median); this is now an
  automatic test (\texttt{ctest}: \texttt{PionCloudValidation}).  Shifting
  $\Lambda$ by the HSS $-1\sigma$ makes 15 of its 17 checks fail.
\item \textbf{Against the original Fortran.}  \texttt{3Var\_theta.f} and
  \texttt{3Var\_x.f} (T.~Hobbs), compiled and run with the same settings,
  agree with \picloud{} to 0.07--0.16\% on the same grid once the
  Fortran's end-point Simpson weight (2 instead of 1) is aligned; that
  weight is also why the published curves lie $\sim1\%$ above \picloud{}.
\item \textbf{Against an independent publication.}  The pion
  multiplicities $\langle n\rangle_{\pi N}=\int dy\,dk_\perp^2 f$ summed over
  charge states are 0.224 (\texttt{exp\_s}, 1.33~GeV) and 0.310
  (Pauli--Villars, 0.27~GeV), vs.\ 0.23 and 0.31 in McKenney
  \textit{et al.}~\cite{McK16}, Table~I.
\item \textbf{Sum rules.}  GRV92 and GRS99 satisfy the valence number sum
  rule, GRS99 also the momentum sum rule ($1.000\pm0.005$), as unit tests.
\end{enumerate}

\subsection{Bugs fixed}

\begin{description}
\item[GRS99 (\inikey{grv\_version = 99}).] The paper~\cite{GRS99} defines
  $v^\pi=u_v^\pi+\bar d_v^\pi$ (both valence quarks, $\int v=2$); v1.3 used it
  as one flavour in $F_2^\pi=\tfrac59(xV+2xS)$, used the \emph{strange}-sea
  parametrisation (their Eqs.~A.7--A.8) as the light sea, and had the sign
  of the $0.009s^2$ term wrong.  Effect: $F_2^{(\pi N)}$ +107\%.  Now
  $\int V=1$ per flavour and the GRS99 momentum sum is 1; GRS99 differs from
  GRV92 by +5 to +17\% on the TDIS tagged curves.
\item[Default model.] Pauli--Villars with 1.33~GeV (1.33 is the
  \texttt{exp\_s} fit, PV's is 0.27~GeV~\cite{McK16}) $\to$ \texttt{exp\_s}
  with the HSS 1.56~GeV, as in the C interface and the TDIS proposal.  Runs
  that relied on the defaults gave $F_2^{(\pi N)}$ 1.6--1.9$\times$ larger.
\item[Test suite.] With CTEQ6, the tests ran in a directory without the
  table; the Fortran \texttt{STOP} ended the suite with exit status 0
  after $\sim80$ tests and \texttt{ctest} reported ``Passed''.  Now all
  212 unit tests run (and the Calculator throws instead of letting the
  Fortran terminate a host program).
\item[Command line.] Nine options listed by \texttt{--help}
  (\texttt{--grv}, \texttt{--nucleon}, \texttt{--precision},
  \texttt{--inclusive}, \texttt{--verbose}, \texttt{--xmin-th}, \dots) were
  never parsed; they work now.
\item[Odd step counts.] The Simpson weights were wrong for an odd number of
  intervals ($-0.4\%$ for \inikey{nk = 201}); a 3/8-rule tail makes any $n$
  exact for cubics.  Even $n$: unchanged.
\item[$\Delta$ + neutral.] \texttt{pi\_delta}/\texttt{rho\_delta} with
  \inikey{dissociation = neutral} silently returned $F_2=0$; now an error.
\end{description}

\subsection{New features}

\begin{description}
\item[\inikey{kbin\_method = exact} --- NEW, and the DEFAULT since v1.4.]
  The $|\vec k|$ window and the angular cuts are solved analytically in
  $u=k_T^2$ (at most two intervals at each $y$) and integrated with
  Gauss--Legendre.  It reaches 0.002\% in 0.3~s, where the Fortran grid needs
  $\sim15$~s for 0.25--8\% (errors concentrated near the kinematic end point),
  and halves the maximum deviation from the published curves.  Relative to
  the grid at the Fortran settings, kbin results change by $\le0.3\%$
  (median), typically 2--6\% near the end of each curve, and up to 35\% in
  the narrow $|\vec k|=60$--100~MeV bin where the grid is not converged.
  \textbf{The ORIGINAL Fortran algorithm remains available} and reproduces
  v1.3 bit for bit:
  \begin{center}
  \begin{tabular}{ll}
  input file & \inikey{kbin\_method = grid} \\
  command line & \texttt{--kbin-grid} \quad(or \texttt{--kbin-method grid}) \\
  C / Python & \texttt{pioncloud\_set\_kbin\_method(0)} \\
  C++ & \code{p.kbin\_method = PionCloud::KBIN\_GRID;}
  \end{tabular}
  \end{center}
  Every kbin run prints the method used and records it in
  \texttt{<base>\_params.txt} and in the header of \texttt{<base>\_xscan.dat}.
\item[\inikey{charge\_states = total}.] Sum over charge states (the
  ``fully integrated'' curves); replaces the manual $\times3$ / $\times\tfrac32$.
\item[\inikey{q2\_fixed}.] Fixed $Q^2$ instead of $Q^2(x)$ at fixed electron angle.
\item[$\rho\Delta$ channel] (\inikey{contribution = rho\_delta}), ported
  in v1.3 but unreachable; not validated against a published curve.
\item[\inikey{pion\_strange}.] Optional strange quarks in $F_2^\pi$.
\item[Pluggable models (\texttt{Models.hh}).] \code{SplittingModel} and
  \code{PionSFModel} interfaces: a new splitting function (e.g.\ chiral EFT,
  kaon cloud) or meson PDF is one class, injected into the Calculator or
  registered by name (\inikey{splitting\_model}, \inikey{pion\_sf\_model}).
  See the header of \texttt{Models.hh} and \texttt{CONTRIBUTING.md}.
\end{description}

\subsection{Reproducing v1.3 results}
\label{sec:migration}

\begin{center}
\begin{tabular}{p{5.2cm}p{9cm}}
\toprule
\textbf{If your v1.3 run \dots} & \textbf{add to the v1.4 input file} \\
\midrule
used the kbin scan (any) & \inikey{kbin\_method = grid} (or \texttt{--kbin-grid}) \\
did not set \inikey{form\_factor}/\inikey{lambda} & \inikey{form\_factor = pauli\_villar}, \inikey{lambda = 1.33}
  (the old default; physically inconsistent, see Sec.~\ref{sec:v14}) \\
used \inikey{grv\_version = 99} & cannot be reproduced on purpose: v1.3 GRS99 was wrong \\
used an odd number of steps & cannot be reproduced on purpose: v1.3 was wrong by $\sim0.4\%$ \\
\bottomrule
\end{tabular}
\end{center}
Everything else (x and theta scans, all explicit settings, even step counts)
gives identical numbers.

\subsection{Open questions found in v1.4}
\begin{itemize}
\item $\langle n\rangle_{\pi\Delta}$: 0.027 vs.\ 0.06 in~\cite{McK16}
  (factor 2.2), while $\pi N$ agrees.  \textbf{Resolved as a model
  difference} and documented in the note
  \texttt{docs/notes/piDelta\_normalisation.pdf}: the paper's Eq.~(5)
  (chiral-EFT on-shell form), implemented with the same regulator, gives
  0.058; the factor splits into isospin bookkeeping ($\times1.5$) and
  functional form ($\times1.43$), couplings agree to 4\%.  \picloud{} keeps
  the Fortran (Sullivan/HSS) model of the TDIS proposal.
\item The $F_2^{p,n}$ reference curves of the proposal are not reproduced by
  any CTEQ6 set (Sec.~\ref{sec:kbin-notes}).
\end{itemize}

\section{What's new in v1.3}
% ============================================================

\subsection{Nucleon selector}

The reference nucleon for the ratio $F_2^{(\pi N)} / F_2^{\text{nucleon}}$
can now be chosen:

\begin{lstlisting}[style=iniStyle]
nucleon = neutron    # default: F2n via charge symmetry (matches Fortran)
nucleon = proton     # F2p directly from CTEQ6
\end{lstlisting}

\subsection{GRV99 pion PDF}

An updated 1999 pion PDF parametrisation is available alongside the
default GRV92:

\begin{lstlisting}[style=iniStyle]
grv_version = 92    # default: GRV92, matches original Fortran
grv_version = 99    # GRS99 (Gluck-Reya-Schienbein 1999)
\end{lstlisting}
\textbf{Warning:} the v1.3 implementation of this set was wrong (valence
counted twice, strange sea used as light sea; $F_2^{(\pi N)}$ about $2\times$
too large).  It is corrected in v1.4 (Sec.~\ref{sec:v14}); results obtained
with \inikey{grv\_version = 99} before v1.4 must be redone.

\subsection{Precision preset}

Sets \inikey{ny} and \inikey{nkt} together for the kbin scan:

\begin{lstlisting}[style=iniStyle]
precision = fast          # ny=20,  nkT=500   -- quick checks
precision = normal        # ny=50,  nkT=2000  -- development
precision = publication   # ny=100, nkT=50000 -- matches Fortran
precision = custom        # use ny/nkT directly
\end{lstlisting}
With \inikey{precision = custom} (the default when \inikey{precision} is
not given) the \inikey{ny}/\inikey{nkt} values of the input file, or the
built-in defaults \inikey{ny=100}, \inikey{nkt=50000}, are used.

\subsection{Inclusive mode shortcut}

Removes all kinematic cuts, giving the fully inclusive
$F_2^{(\pi N)}(x)$ \emph{of the selected charge state} without setting
four parameters by hand.  Multiply by 3 (\texttt{neutral}) or $3/2$
(\texttt{charge\_exchange}) to obtain the violet ``fully integrated''
curve of the published figures, which sums both charge states:

\begin{lstlisting}[style=iniStyle]
inclusive_mode = true
\end{lstlisting}

Equivalent to setting \inikey{cosph\_min=0}, \inikey{cosph\_max=1},
\inikey{k\_min=0.001}, \inikey{k\_max=10.0}.

\subsection{Verbosity control}

\begin{lstlisting}[style=iniStyle]
verbose = false    # suppress all stdout (for library/generator embedding)
\end{lstlisting}

\subsection{Angular cut in degrees}

Aliases for \inikey{cosph\_min}/\inikey{cosph\_max}:

\begin{lstlisting}[style=iniStyle]
angle_min_deg = 30.0    # lower polar angle -> cosph_max = cos(30) = 0.866
angle_max_deg = 70.0    # upper polar angle -> cosph_min = cos(70) = 0.342
\end{lstlisting}

\subsection{CTEQ6 table directory}

Allows running from an arbitrary working directory:

p.cteq6_table_dir = "/path/to/cteq6_tables";
// Calculator chdir()s there before CTEQ6::init(), then restores cwd.
\end{lstlisting}

\subsection{Single-point eval() for generator use}

\begin{lstlisting}[style=cppstyle]
Calculator calc(p);
double f2pi = calc.eval(x, Q2);   // Q2 <= 0: computed from E,x,theta_e
\end{lstlisting}

Returns $F_2^{(\pi N)}(x,Q^2)$ for one point. Always silent regardless

\begin{lstlisting}[style=cppstyle]

\section{Worked examples: the published TDIS figures}
\label{sec:validation}
% ============================================================

The Fortran codes ported in \picloud{} were written by T.~Hobbs for the
pion-cloud calculations of the JLab TDIS proposal PR12-15-006~\cite{TDIS15}

\paragraph{How the comparison was made.}
The proposal figures are vector graphics (\textsc{xmgrace}).  Each curve

the page to SVG and calibrating on the axis frame and major tick marks.

\begin{lstlisting}[style=bashstyle]

for $F_2^{p,n}$, the $s$-dependent exponential form factor
(\inikey{form\_factor = exp\_s}) with $\Lambda=1.56$~GeV and

6               & $\pi N$, $\rho N$, $\pi\Delta$ & $+0.7$--$1.6\%$ & $7\%$ \\
37              & $\pi N$, $\rho N$, $\pi\Delta$ & $+0.3$--$0.6\%$ & $2.8\%$ \\
5, 6, 37        & inclusive $\times$ isospin & $-0.1\%$ & $0.3\%$ \\
5, 6, 37        & $F_2^p$, $F_2^n$ (CTEQ6M) & $+3.5$--$6.8\%$ & $7.5\%$ \\
\bottomrule
\end{tabular}
\end{center}
``Bulk'' means points where the published curve is within a factor 100
of its maximum; closer to the kinematic end points both curves fall
steeply to zero and the ratio is not meaningful.  The largest bulk
deviations (Fig.~6) occur at $x\approx0.18$, just before the end point.

Lessons for reproducing the published curves:
\begin{itemize}
\item \textbf{Electron angle.}  Use $\theta_e=35^\circ$ in all modes.
  With $12^\circ$ the tagged curves come out 3--11\% higher at
  $x\gtrsim0.15$.
\item \textbf{Charge states.}  One run is one charge state.  The
  ``fully integrated'' violet curves are the sum over charge states:
  $3\times$ neutral, or $\tfrac32\times$ charge exchange (agreement $0.1\%$);
  since v1.4 use \inikey{charge\_states = total}.
\item \textbf{Integration.}  With \inikey{kbin\_method = exact} (v1.4) the
  maximum deviations of the kbin curves halve (Fig.~6: 6--7\% $\to$ 3.5\%;
  Fig.~37: $\sim2.5\%\to$ 1--1.6\%): most of the end-point deviation was an
  artefact of the Fortran $k_T$ grid.
\item \textbf{$\pi\Delta$ cut-off.}  The $\pi\Delta$ channel uses
  \inikey{lambda\_delta}.  Changing \inikey{lambda} does not affect it.
\item \textbf{Angular window.}  $\cos\phi_k>0$ always, so
  $[30^\circ,180^\circ]$ is entered as \inikey{cosph\_min = 0}.  For
  $x\ge0.05$, $|\vec k|\le400$~MeV the $70^\circ$ cut changes the result
  by $<0.5\%$.
\item \textbf{$F_2^{p,n}$.}  The CTEQ6M $F_2$ used for the ratio lies
  3--7\% above the orange curves of the proposal.  This affects only the
  reference curves and the ratio, not $F_2^{(\pi N)}$; the PDF set or
  order used for the published curves is not documented (open item).
\item \textbf{Not reproduced here.}  Fig.~35 of~\cite{TDIS15} (ratios with
  projected data, a ROOT raster image) and Fig.~45 (the $|\vec k|$
  dependence; there is no $|\vec k|$-scan mode yet).
\end{itemize}

\subsection{RunParams (PhysicsParams.hh)}

#include "PhysicsParams.hh"
PionCloud::RunParams p;
p.flag       = PionCloud::FLAG_PION;
p.typ        = PionCloud::FF_EXP_S;
p.L          = 1.56;
p.dis        = PionCloud::DIS_CHARGE_EXCHANGE;
p.E          = 11.0;
p.theta_e    = 12.0;
p.kmin       = 0.060;
p.kmax       = 0.250;
p.cosph_min  = 0.342;
p.cosph_max  = 0.866;
p.ny         = 100;
p.nkT        = 5000;
p.outputMode = PionCloud::OUT_NONE;  // no file I/O
\end{lstlisting}

\subsection{Calculator (Calculator.hh)}

The integration engine.  No I/O dependencies.

\begin{lstlisting}[style=cppstyle]
#include "Calculator.hh"
PionCloud::Calculator calc(p);

PionCloud::ScanResults res;
calc.runXScan(res);         // x-scan (3Var_x.f)
calc.runThetaScan(res);     // theta-scan (3Var_theta.f)
calc.runKBinScan(res);      // kbin-scan (f2pi_sub.f90)

// Or run the mode selected by p.scanMode:
PionCloud::ScanResults res2 = calc.runAll();
\end{lstlisting}

\textbf{Public methods:}

\begin{center}
\begin{tabular}{lp{8cm}}
\toprule
\textbf{Method} & \textbf{Description} \\
\midrule
\code{runXScan(out)}     & x-scan; fills \code{out.xScan} \\

\subsection{User models (Models.hh, v1.4)}

The calculation needs two physics ingredients, each behind an interface:
\begin{lstlisting}[style=cppstyle]
struct SplittingModel {               // f(y, kT) per d(kT^2)
    virtual double f(double y, double kT) const = 0;
    virtual std::string name() const = 0;
};
struct PionSFModel {                  // F2 of the meson
    virtual double F2(double xpi, double Q2) const = 0;
    virtual std::string name() const = 0;
};
\end{lstlisting}
A new model is one class; it is either injected,
\begin{lstlisting}[style=cppstyle]
struct MyChiralPiN : PionCloud::SplittingModel { ... };
PionCloud::Calculator calc(p, std::make_shared<MyChiralPiN>());
\end{lstlisting}
or registered by name and then selected from any input file with
\inikey{splitting\_model = piN\_chiralEFT}:
\begin{lstlisting}[style=cppstyle]
PionCloud::ModelRegistry::addSplitting("piN_chiralEFT",
    [](const PionCloud::RunParams &p){ return std::make_shared<MyChiralPiN>(); });
\end{lstlisting}
All scans, outputs and the C interface then use it.  The built-in models
(\code{BuiltinSplitting}, \code{BuiltinPionSF}) wrap the Fortran ports and
give bit-identical results.  Check a new splitting function's normalisation
against a published multiplicity (see \texttt{CONTRIBUTING.md}).

\textbf{Private static helpers:}

\begin{center}
\begin{tabular}{lp{8cm}}
\toprule
\textbf{Method} & \textbf{Description} \\
\midrule
\code{kMag(kT, y)}   & 3D recoil proton momentum magnitude from $(k_T, y)$ \\
\code{cosPhi(kT, y)} & Proton polar angle $\cos\phi_k$ from $(k_T, y)$ \\
\bottomrule
\end{tabular}
\end{center}

\subsection{ScanResults and data structures (Results.hh)}

Plain structs with no ROOT or file-system dependencies:

\begin{lstlisting}[style=cppstyle]
struct XScanPoint {
    double x;           // Bjorken-x
    double Q2;          // Q^2 at this x [GeV^2]
    double F2piK;       // F2^pi(x) integrated over phase space
    double F2piMoment;  // running integral
    double F2n;         // F2^n from CTEQ6 (0 if unavailable)
    double ratio;       // F2piK / F2n
};

struct ThetaScanPoint {
    double theta_deg;   // hadron production angle [degrees]
    double F2piK;       // F2^pi(theta_h)
    double F2piMoment;  // running integral
};

struct ScanResults {
    std::vector<XScanPoint>     xScan;
    std::vector<ThetaScanPoint> thetaScan;
    double F2pi0_x     = 0.0;  // first moment (Simpson)
    double F2pi0_theta = 0.0;
};
\end{lstlisting}

\subsection{InputReader (InputReader.hh)}

Parses INI-style input files.  Optional --- \code{RunParams} can be
set directly in C++ without using this class.

\begin{lstlisting}[style=cppstyle]
#include "InputReader.hh"
PionCloud::InputReader reader;
PionCloud::RunParams p = reader.read("myrun.in");

if (reader.hasErrors()) {
    reader.printDiagnostics();
    return 1;
}

// Generate a fully documented template file:
PionCloud::InputReader::writeTemplate("myrun.in");
\end{lstlisting}

\subsection{OutputWriter (OutputWriter.hh)}

Writes ASCII and/or ROOT output.  Controlled by
\code{p.outputMode}.

\begin{lstlisting}[style=cppstyle]
#include "OutputWriter.hh"
PionCloud::OutputWriter writer(p, "MyRun");
writer.write(results);
\end{lstlisting}

\subsection{CTEQ6 (CTEQ6.hh)}

C++ wrapper for the CTEQ6 Fortran PDF library.  Handles all
float/double casts internally.

\begin{lstlisting}[style=cppstyle]
#include "CTEQ6.hh"
PionCloud::CTEQ6::init();                        // call once
double f2n = PionCloud::CTEQ6::F2neutron(x, Q2);
double f2p = PionCloud::CTEQ6::F2proton (x, Q2);
double xfu = PionCloud::CTEQ6::xfx(1, x, Q);   // u-quark
\end{lstlisting}

\textbf{Available functions:}

\begin{center}
\begin{tabular}{lp{8cm}}
\toprule
\textbf{Function} & \textbf{Description} \\
\midrule
\code{init(set)}          & Initialise PDF tables (default: CTEQ6M, iset=1) \\
\code{xfx(iparton,x,Q)}  & $x\,f(x,Q)$ for parton code \code{iparton} \\
\code{F2neutron(x,Q2)}   & $F_2^n$ via charge symmetry \\

\section{Using PionCloud as a library}
% ============================================================

\picloud{} is built as a static library \texttt{libPionCloudLib.a}.
Any C++ program can embed it:

\begin{lstlisting}[style=bashstyle]
# In your CMakeLists.txt:
add_subdirectory(PionCloud)
target_link_libraries(MyProgram PRIVATE PionCloudLib)
\end{lstlisting}

\begin{lstlisting}[style=cppstyle]
#include "PhysicsParams.hh"
#include "Calculator.hh"
#include "Results.hh"

using namespace PionCloud;

RunParams p;
p.flag       = FLAG_PION;
p.typ        = FF_EXP_S;
p.L          = 1.56;
p.dis        = DIS_CHARGE_EXCHANGE;
p.E          = 11.0;  p.theta_e = 12.0;
p.kmin       = 0.060; p.kmax    = 0.250;
p.cosph_min  = 0.342; p.cosph_max = 0.866;
p.ny  = 100;  p.nkT = 5000;
p.outputMode = OUT_NONE;   // no files written
p.scanMode   = "kbin";

Calculator calc(p);
ScanResults res;
calc.runKBinScan(res);

for (auto &pt : res.xScan)
    printf("x=%.4f  Q2=%.4f  F2piK=%.6e  F2n=%.6e  ratio=%.6e\n",
           pt.x, pt.Q2, pt.F2piK, pt.F2n, pt.ratio);
\end{lstlisting}

For event-by-event use, \code{Calculator::eval(x, Q2)} returns a single
point silently, \code{p.verbose = false} suppresses all output, and
\code{p.cteq6\_table\_dir} sets where the CTEQ6 tables are read from
(see ``What's new in v1.3'').

\textbf{Current limitation} (see \texttt{TODO.md}): CTEQ6 is not
thread-safe (Fortran \texttt{COMMON} blocks); do not evaluate from
several threads at once.

\section{Known issues and TODO}
% ============================================================

The complete, current list is maintained in \texttt{TODO.md}.
Main open items:

\begin{enumerate}
\item \textbf{$\pi\Delta$ charge states}: the meaning of the Fortran
  factor $\tfrac23$ (note \texttt{docs/notes/piDelta\_normalisation.pdf}).
\item \textbf{Sum of channels} ($\pi N+\rho N+\pi\Delta$ in one run); the
  sum over charge states exists since v1.4.
\item \textbf{$|\vec k|$-scan and t-scan modes} (Fig.~45 of~\cite{TDIS15};
  $F_2^{(\pi N)}$ vs.\ $-t$).
\item \textbf{LHAPDF backend} for modern pion/nucleon PDFs and
  \textbf{Python bindings}; both need packages not installed on the
  development machine.  The \code{PionSFModel} interface is the hook.
\item \textbf{Thread safety}: CTEQ6 Fortran \texttt{COMMON} blocks.
\item \textbf{$F_2^{p,n}$} reference curves of the proposal not reproduced
  by any CTEQ6 set.
\end{enumerate}
